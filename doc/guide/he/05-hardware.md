# 05 - חומרה ותתי־מערכות לשימוש חוזר

[English](../05-hardware.md) | [תוכן המדריך](../../../README.he.md#learning-path) | דוגמאות: [02 מנוע](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/examples/Example02Motor.java), [03 סרוו](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/examples/Example03Servo.java) | הבא: [נהיגה](06-driving.md)

## מיפוי התקן פיזי פעם אחת

הגדירו את ההתקן ב־Robot Controller, תנו לו שם משמעותי והשתמשו בדיוק באותה מחרוזת בקוד. שם כמו `intake` מתאר את תפקידו; מספר יציאה לבדו אינו עושה זאת. `hardwareMap.get(DcMotorEx.class, "exampleMotor")` דורש מנוע תואם שהוגדר. סרוו זקוק ל־`Servo.class`, ואילו סרוו סיבוב רציף משתמש ב־API אחר של SDK ואינו מכוסה ב־ServoSubsystem.

צרו מופע תת־מערכת אחד לכל מנגנון ב־OpMode ושתפו אותו בין הפקודות. שני מופעים שעוטפים אותו מנוע מטעים את מנגנון הבעלות: המתזמן רואה בעלים שונים לאותה חומרה. קבצו מנגנונים לפי צורכי תיאום אמיתיים ולא לפי מספר קובצי המקור הרצוי.

## תחומי האחריות של MotorSubsystem

ל־[MotorSubsystem.java](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/subsystems/MotorSubsystem.java) יש שני בנאים. בנאי HardwareMap מאתר התקן לפי שם. האחר מקבל `DcMotorEx` שכבר סופק. `SubsystemBase` רושם את האובייקט במתזמן אוטומטית.

הבנייה מגדירה כיוון, `RUN_WITHOUT_ENCODER`, התנהגות BRAKE באפס הספק, הספק התחלתי אפס ופקודת עצירה רציפה כברירת מחדל. אלה בחירות מפורשות לדוגמת מנגנון איסוף או מסוע בחוג פתוח. BRAKE מתנגד לגלישה; הוא אינו בקר לשמירת מיקום. אפשר שקריאת מקודד תהיה זמינה גם כשהמנוע בחוג פתוח.

`setPower()` מקבלת הספק מנורמל, דוחה קלט שאינו סופי ומגבילה לטווח ‎[-1, 1]. `velocity()` מדווחת טיקים של מקודד לשנייה לפי ה־SDK. `run(DoubleSupplier)` היא מפעל פקודות: היא קוראת את ההספק המסופק בכל מחזור execute, דורשת תת־מערכת זו ועוצרת בביטול. `stopCommand()` סופית; `defaultStopCommand()` רציפה.

כדי להפוך אותה למנגנון האיסוף שלכם:

1. העתיקו את MotorSubsystem אל `IntakeSubsystem.java` ושנו את שם המחלקה והבנאים.
2. בחרו את השם המוגדר והכיוון הפיזי בקריאת הבנאי מתוך ה־OpMode.
3. הוסיפו מפעלי פעולות כגון `intake()` ו־`eject()` עם מגבלות הספק מדודות.
4. קשרו A לאיסוף ו־B לפליטה ב־TeleOp שלכם. שמרו על הדרישות והניקוי.
5. בדקו אתחול באפס, כיוון, שחרור, ביטול ולבסוף STOP.

אל תעתיקו סל״ד, PIDF או יעדי מהירות ממנוע הירי הישן למנגנון שונה. הם שייכים לרובוט ההוא ונשמרים בארכיון.

## מצבי בקרה ויחידות

| מצב | משמעות הבקשה | עבודה נוספת |
|---|---|---|
| SDK `RUN_WITHOUT_ENCODER` | הספק מנורמל בחוג פתוח | קביעת הספק וכיוונים מתאימים |
| SDK `RUN_USING_ENCODER` עם `setVelocity()` | חוג סגור בטיקים לשנייה או ביחידות זווית שהוגדרו | אימות הגדרת המנוע, רזולוציית המקודד ו־PIDF |
| SDK `RUN_TO_POSITION` | הבקר נע לעבר יעד מיקום מקודד | קביעת יעד לפני כניסה למצב; הוספת איפוס ייחוס, סבולת, timeout וניקוי |
| בקר מהירות תוכנתי של ספרייה | משוב ובקרה מקדימה ייחודיים לספרייה | כוונון הבקר ההוא; SDK PIDF עשוי שלא להשפיע עליו |

בחרו במכוון גורם אחד האחראי לבקרה. להמרת טיקים לשנייה לסיבובי ציר לשנייה חלקו במספר הטיקים האמיתי לסיבוב, בהתחשב בתמסורת ובמיקום המקודד. סל״ד נומינלי בקטלוג אינו מהירות מדודה תחת עומס. לעולם אל תערבבו אינצ׳ים, סנטימטרים וטיקים ביעד אחד ללא תיעוד.

הדוגמה הכללית אינה מגדירה התרעות זרם, מפסקי קצה, איפוס ייחוס או נעילת תקלה. הוסיפו אותם למנגנון האמיתי. התרעת זרם ב־SDK דורשת סף שנבחר ממדידות החומרה; בדיקת `isOverCurrent()` ללא סף שימושי אינה מספיקה. העבירו תנאי עצירה משולב ל־MotorCommands או צרו פקודה ייעודית, והחליטו אם החזקת כפתור תאפשר ניסיון חוזר אחרי שהתקלה נעלמת.

## ServoSubsystem

[ServoSubsystem.java](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/subsystems/ServoSubsystem.java) ממפה סרוו מיקום בלי לשלוח בקשת מיקום בבנאי. `setPosition()` מאמתת את הטווח ‎[0, 1]. `moveTo(DoubleSupplier)` קוראת את המיקום באתחול הפקודה המיידית ודורשת את תת־המערכת. היא מסתיימת מיד לאחר שליחת הבקשה.

המיקומים המנורמלים אינם מעלות ואינם משוב. Example03 משתמשת ב־0.45/0.55 רק כבקשות דוגמה קטנות; יש למדוד את גבולות המנגנון בפועל. סרוו יכול לנוע במהירות לכל אחד מהיעדים. STOP אינו מחזיר אותו אוטומטית למצב בטוח, וביטול אינו מבטל בדיעבד פקודת סרוו שכבר הסתיימה. הגדירו מדיניות כיבוי מפורשת למנגנון האמיתי; אין נקודת קצה בטוחה אוניברסלית.

תרגיל: צרו `ClawSubsystem` החושפת `openCommand()` ו־`closeCommand()` עם מיקומים מדודים בעלי שמות. הוסיפו את התופסן ל־TeleOp שהועתק משיעור המנוע, והסבירו מדוע התופסן ומנגנון האיסוף יכולים לפעול במקביל. בדקו את החיבור המכני כשזרוע הסרוו והמנגנון מוגדרים כראוי לפני הרחבת טווח התנועה.
