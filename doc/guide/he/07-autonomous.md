# 07 - אוטונומי עם Pedro ו־PoseFactory

[English](../07-autonomous.md) | [תוכן המדריך](../../../README.he.md#learning-path) | דוגמה: [06 אוטונומי](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/examples/Example06Autonomous.java) | הבא: [Panels וכוונון](08-panels-tuning.md)

## דרישות מוקדמות ובנייה

האוטונומי משתמש באותה מערכת הנעה של ארבעה מנועי mecanum,‏ Pinpoint וגלגלי אודומטריה כמו TeleOp. בנוסף נדרשים אמידת מיקום שנבדקה במדידות והגדרות תנועה, בקרה ובלימה מכווננות. הדוגמה מושבתת משום שבנייה מוצלחת אינה מאמתת מדידות אלה.

Constants יוצר שלושה אובייקטים משתפים פעולה: `Mecanum` ממיר בקשות הספק הנעה לארבעה מנועים, `PinpointLocalizer` מספק תנוחה ומהירות ו־`Foresight` מחשב תיקוני מסלול. `new Follower(localizer, drivetrain, algorithm)` מחבר אותם. כל אתחול יוצר בקרים ותמונות מצב חדשות של התצורה. PedroDrive עוטף את העוקב כתת־מערכת שבבעלות המתזמן.

## תנוחות, יחידות ועקומות

השתמשו במפעלים המשותפים:

<div dir="ltr">

```java
Pose start = Constants.FIELD_POSES.of(0, 0, 0);   // Heading supplied in degrees.
Pose end = Constants.FIELD_POSES.of(12, 0, 90);   // Stored heading is PI/2 radians.
Pose measured = Constants.RADIAN_POSES.of(x, y, headingRadians);
```

</div>

בשורה הראשונה הזווית נמסרת במעלות; בשנייה הזווית הנשמרת היא PI/2 רדיאנים. האובייקט המתקבל הוא עדיין Pose של Pedro; המפעלים מגדירים רק מוסכמת קלט והתמרות אופציונליות. שמרו טריגונומטריה, `withHeading(...)`, טלמטריית עוקב וכיוונים מחושבים ברדיאנים. בייבוא סטטי של `FIELD_POSES` אפשר לכתוב ישירות `FIELD_POSES.of(...)`.

`Paths.line(start, end)` יוצר מסלול ישר במרחב. `.linear(start, end)` מבצע אינטרפולציה של הזווית בין הזוויות השמורות; יצירת קו לבדה אינה קובעת מדיניות זווית. `Paths.curve(...)` יוצר עקומת בזייה: התנוחה הראשונה והאחרונה הן קצוות, והאמצעיות הן נקודות בקרה המעקמות את המסלול. בדרך כלל הרובוט אינו חייב לעבור בנקודות הביניים. `Paths.path(first, second)` מחבר מקטעים. `.constant(pose)` מספק זווית קבועה; `.tangent()` יעקוב במקום זאת אחר המשיק לעקומה.

Example06 נוסעת מ־(0,0,0 מעלות) אל (12,0,90 מעלות), ממתינה 500 מילישניות ועוקבת אחר עקומת חזרה עם נקודות הבקרה (12,12) ו־(0,12), עד (0,0,0 מעלות). תנוחת ההתחלה תואמת לזווית המסלול הראשון. בחרו התחלה ידועה ומשמעותית פיזית לפני העתקה לשגרת מגרש.

## פקודות והתקדמות

הדוגמה מתזמנת SequentialCommandGroup במהלך initialize, אך מחלקת הבסיס אינה מריצה את המתזמן עד START. מתודת periodic של PedroDrive מעדכנת את העוקב פעם אחת בכל לולאה פעילה. `FollowPathCommand` מתחילה מסלול וממתינה לסיום העוקב; החזקה בקצה ו־timeout הם התנהגות האלגוריתם, ואינם הוכחה לדיוק פיזי.

ParallelDeadlineGroup עוקבת אחר המסלול הראשון בזמן שפקודה אחרת מעדכנת טקסט שלב. לתיאום מנגנון אמיתי, החליפו את פקודת השלב העצמאית בפקודת תת־מערכת מתאימה וספקו והגדירו את החומרה. אין להריץ במקביל שתי פקודות הדורשות אותה תת־מערכת. הוסיפו את דרישת ההנעה לשגרת ההורה, משום ש־FollowPathCommand אינה מכירה את המעטפת שלנו. אל תתזמנו פקודת מנגנון בנפרד מתוך callback אם שגרת ההורה כבר מחזיקה בו.

השתמשו ב־`.withTimeout(milliseconds)` אם דרושה מגבלת זמן, אך החליטו במפורש מה קורה בכישלון: אחרת מסלול שנגמר עקב timeout עלול להמשיך לפעולת ניקוד כאילו הגיע. WaitCommand שבדוגמה היא השהיה שאינה חוסמת, ולא מגבלת זמן למסלול. STOP מבטל את השגרה ומאפס את מערכת ההנעה.

## שדות Foresight למדידה ולהבנה

| שדות | יחידות והשפעה | מצב בתבנית |
|---|---|---|
| `FORWARD_VELOCITY`, `STRAFE_VELOCITY` | אינצ׳ים לשנייה; מהירות קדימה והצדה בת השגה | אומדני ברירת מחדל מהספרייה הישנה, לא מדידות רובוט |
| `FORWARD_DECELERATION`, `STRAFE_DECELERATION` | אינצ׳ים לשנייה בריבוע, ערך חיובי להאטה טבעית באפס הספק | גדלים מהספרייה הישנה; יש לאפיין את הרובוט |
| `TRANSLATIONAL_P`, `TRANSLATIONAL_STATIC` | הגבר משוב מיקום והספק תיקון סטטי | ערכי התחלה משותפים לבקרים נפרדים קדימה והצדה |
| `HEADING_P`, `HEADING_STATIC` | הגבר משוב זווית והספק תיקון סטטי | אומדני התחלה; רכיבי אינטגרל ונגזרת אפס |
| `FORWARD_LINEAR_BRAKE`, `STRAFE_LINEAR_BRAKE` | מקדמי העתק המכפילים מהירות; שניות | אומדני התחלה אפס |
| `FORWARD_QUADRATIC_BRAKE`, `STRAFE_QUADRATIC_BRAKE` | מקדמים המכפילים מהירות בגודל שלה; שניות בריבוע לאינץ׳ | אומדני התחלה של תאוטה קבועה |
| `HEADING_LINEAR_BRAKE`, `HEADING_QUADRATIC_BRAKE` | מודל העתק זוויתי | אומדני התחלה אפס; יש לאפיין מקדמי זווית |
| `parametricTConstraint` | בדיקת קצה משתמשת ב־t >= 1 - 0.01 | מוגדר ב־createForesightConfig |
| `timeoutConstraint` | מגבלת זמן קצה של 100 מילישניות | אינה מגבלת זמן לכל האוטונומי |

גלישה ובלימה משתמשות תחילה בבקרה מקדימה יחסית למהירות, `1 / FORWARD_VELOCITY`; זו אינה המרה מדויקת של PIDF הנעה קודם. מטריצות אלכסוניות מקודדות מקדמי בלימה עצמאיים קדימה והצדה; וקטור הזווית מחזיק את הרכיבים הלינאריים והריבועיים. מאתחלי הרכיבים הריבועיים משתמשים בקבועים מפורשים, ולכן שינוי שדות התאוטה אינו מחשב אותם מחדש. עריכת שדות ב־Panels אינה בונה מחדש בקרים קיימים: אתחלו מחדש לאחר שינוי תמונות מצב אלה של התצורה.

## בניית שגרה בהדרגה

אמתו תחילה אמידת מיקום, אחריה קו ישר קצר, נקודת קצה וזווית, עקומה, מקטע שני ורק אז תיאום מנגנונים. תעדו תנוחה בפועל מול מבוקשת וזמני סיום. מסלול המצויר היטב על נייר עדיין עלול לדרוש תאוצה או מרווח שאין לרובוט.

תרגיל: שנו את קצה הקו ל־18 אינץ׳ תוך שמירה על זווית ההתחלה. הוסיפו מקטע ישר שלישי והסבירו את אינטרפולציית הזווית שלו לפני ההתקנה. שמרו קואורדינטות יעד ייחודיות למשחק ושיקוף ברית בשגרת הקבוצה ולא בקבועים הכלליים.
