# 09 - פתרון בעיות

[English](../09-troubleshooting.md) | [תוכן המדריך](../../../README.he.md#learning-path) | הקודם: [Panels וכוונון](08-panels-tuning.md) | הבא: [עבודת צוות](10-workflow.md)

## קריאת שגיאות סביבת הפיתוח

תהליך העבודה הרגיל הוא עריכה, בחירת הבקר ותצורת יישום Android ולחיצה על **Run ▶**. הפעולה בונה ומתקינה אוטומטית. בצעו Sync אחרי שינוי תלויות או הגדרות בנייה, או כשסביבת הפיתוח מבקשת.

כשמשהו נכשל, פתחו את חלון **Build**,‏ **Run** או **Sync**, הרחיבו את השגיאה הרלוונטית הראשונה ועברו לקובץ המקושר. תקנו את הגורם לפני ניסיון נוסף. בהתקנה ודאו שתצורת ההרצה הנבחרת היא יישום Android.

## אבחון בעיות נפוצות

| תסמין | בדיקה ופעולה הבאה |
|---|---|
| Gradle אינו מתחיל, גרסת Java או class אינה נתמכת | פתחו Settings > Build, Execution, Deployment > Build Tools > Gradle ובחרו Java 25 בתור Gradle JDK/JVM, ואז סנכרנו. רמת השפה בעורך היא הגדרה נפרדת. |
| שרשרת כלים של Java לא נמצאה | הרחיבו את שגיאת Sync/Build כדי לזהות את ה־JDK הנדרש; קוד היישום דורש Java 8 בעוד Gradle רץ על Java 25. הוסיפו או הורידו את ה־JDK החסר דרך פקדי ה־IDE ובדקו גישת הורדה לפני שינוי גרסאות המהדר. |
| מיקום או פלטפורמת Android SDK חסרים | בחרו מיקום נכון והתקינו חבילות נדרשות ב־SDK Manager, ואז סנכרנו. אפשרו ל־IDE לעדכן הגדרות SDK מקומיות; שמרו נתיבי מחשב מחוץ ל־Git. |
| פרויקט Gradle של TeamCode לא נמצא | בחרו את יישום Android בשורש ב־Run > Edit Configurations, או את פרויקט השורש בתצורות בדיקת Gradle. TeamCode היא תיקיית מקורות מוגדרת. |
| לא ניתן לפתור תלות | קראו איזה artifact או מאגר נכשל; בדקו רשת ותצורת מאגרים. מצב לא מקוון עובד רק עם artifacts שבמטמון. |
| מחלקות Panels כפולות או שילוב הגדרות לא תואם | שמרו על גרסת Sloth FullPanels המוצהרת ובדקו תלויות; אל תוסיפו לצדה את הגרסה הרגילה. |
| OpMode אינו מופיע ב־Driver Station | הדוגמאות ו־Tuning מסומנים `@Disabled`. הפעילו עותק ששמו שונה, בדקו את ה־annotation, לחצו Run ▶ של יישום Android ובדקו אם נשאר קוד Sloth ישן. |
| INIT נכשל באיתור חומרה | התאימו שמות, כולל אותיות גדולות וקטנות, וטיפוסי התקנים לתצורת Robot Controller שנבחרה. שיעורי נהיגה דורשים גם Pinpoint וגם ארבעה מנועים. |
| פקודה אינה רצה או מפריעה שוב ושוב לאחרת | שמרו `super.run()`, בדקו קישורי כפתורים ודרישות תתי־מערכות והשתמשו במופע אחד לכל מנגנון פיזי. |
| רצף אינו מתקדם | פקודות רציפות צריכות ילד הקובע סיום, timeout או תנאי סיום. השתמשו ב־`stopCommand()` סופית בתוך רצף. הזמנים כאן במילישניות. |
| פעולה המוחזקת בכפתור מתחילה שוב אחרי סיום | `whileHeld` עשויה לתזמן מחדש כשהכפתור נשאר לחוץ. בחרו הפעלה ברגע הלחיצה או נעילת תקלה מפורשת אם ניסיון חוזר אינו מתאים. |
| פקודת סרוו מסתיימת לפני סיום התנועה | סיום אומר שהבקשה נשלחה. הוסיפו תזמון מדוד או משוב אמיתי אם פעולות המשך תלויות בהגעה. |
| הרובוט נע בכיוון שגוי או המיקום נסחף בסיבוב | בדקו סידור גלגלים, כיווני מנועים ומקודדים, סוג גלגלי אודומטריה והיסטים עם סימן לפני כוונון הגברי בקרה. |
| כיוון נהיגה ביחס למגרש שגוי | בדקו סימן ומוצא זווית ומערכת צירים. איפוס תנוחה משנה את מערכת הצירים של המגרש. |
| שינוי ב־Panels אינו משפיע | בדקו אם השדה נקרא בכל לולאה או הועתק באתחול או ביצירת מסלול; בצעו STOP ואתחול מחדש לתמונות מצב. |
| נראה שהקוד המותקן לא השתנה | ודאו התקן נבחר ופלט משימה מוצלח; הסירו קוד Sloth מרוחק ישן לפני התקנה מלאה לפי פרק 08. |

גרסת lint העצמאית נבחרה במכוון עבור מטא־הנתונים של Kotlin בתלויות. אזהרת הגדרה ניסיונית או הוצאה משימוש של Gradle שונה מבדיקה שנכשלה. אל תשדרגו את כל מערך הבנייה רק להשתקת אזהרה ללא בדיקת תאימות.

## אימות על הרובוט

הריצו רק בדיקות חומרה הרלוונטיות לשינוי. לפעולת מנוע בדקו אפס פלט ב־INIT, כיוון בהספק נמוך, שחרור, הפרעה ו־STOP. לסרוו אמתו גבולות מכניים מדודים וזכרו ש־STOP אינו משחזר מיקום. לנהיגה פעלו לפי [פרק 06](06-driving.md#first-drive-verification); למסלולים לפי [פרק 07](07-autonomous.md#build-your-routine-incrementally).

תעדו מה רץ בפועל: גרסת קוד, תצורת חומרה, מדידות ותוצאות שנצפו. סמנו בדיקות הדורשות חומרה כממתינות עד שמישהו מבצע אותן. בניית APK מוצלחת אינה בדיקת נהיגה שהושלמה.
