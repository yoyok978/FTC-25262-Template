# 10 - עבודת צוות והתאמת התבנית

[English](../10-workflow.md) | [תוכן המדריך](../../../README.he.md#learning-path) | הקודם: [פתרון בעיות](09-troubleshooting.md)

## הפיכת המאגר לנקודת ההתחלה של הקבוצה

צרו מהתבנית מאגר בבעלות הקבוצה והשתמשו ב־**Get from VCS / Clone Repository** בסביבת הפיתוח כדי לפתוח את העותק שלכם. לפרויקט קיים השתמשו ב־**File > Open** על תיקיית השורש ונהלו מאגרים מרוחקים דרך **Git > Manage Remotes**. שמרו על גרסאות התלויות עד לבדיקת שדרוג מכוונת. הגדירו שמות, כיווני מנועים ומקודדים, סוג גלגלי אודומטריה והיסטים מדודים לפני נהיגה; הערכים המסופקים אינם מתארים את ההתקנה שלכם.

שמרו את השיעורים הממוספרים הכלליים לעיון. מקמו שגרות קבוצה ב־`opmodes` ואת האחריות למנגנונים ב־`subsystems`. קוד העונה הישנה נשמר ב[ארכיון](../../archive/pre-template/INDEX.md), מחוץ לתיקיות המקור המתקמפלות. עיינו בו כהיסטוריה; העתיקו רק התנהגות שאתם מבינים והתאמתם לספריות ולחומרה הנוכחיות.

## העתקת דוגמה

1. בחרו את השיעור הקטן ביותר המדגים את ההתנהגות הדרושה. שיעורים 01 ו־07 אינם דורשים ציוד היקפי; README מפרט את החומרה לשאר השיעורים.
2. העתיקו את מקור Java מ־`examples` לתיקיית `opmodes` האחות. שנו את החבילה ל־`org.firstinspires.ftc.teamcode.opmodes`.
3. שנו יחד את שם הקובץ והמחלקה הציבורית, למשל `IntakeTeleOp.java` ו־`IntakeTeleOp`. השתמשו בשם תצוגה ייחודי ב־`@TeleOp` או `@Autonomous` ובקבוצה מתאימה.
4. החליפו שמות חומרה, כיוונים ובקשות מספריות בבחירות שנמדדו ברובוט שלכם. העתיקו ושנו שם לתת־מערכת כאשר האחריות משתנה; שנו גם את שמות הבנאים. שמרו מופע תת־מערכת אחד לכל מנגנון פיזי ב־OpMode.
5. הסירו `@Disabled` מהעותק. השאירו אותו בדוגמה הלימודית המקורית. שמרו על `reset()`,‏ `super.run()` וביטול פקודות וניקוי הנעה בעת התאמת מחזור החיים.
6. עדכנו את הערת הפתיחה בעותק עם חומרה נדרשת, בקרות ושלבי אימות. בחרו את הבקר ותצורת יישום Android ולחצו **Run ▶** לבנייה ולהתקנה. לחלופין השתמשו בתצורת Sloth האופציונלית מפרק 08. בחרו את שם ה־OpMode החדש ב־Driver Station. עריכות Java רגילות אינן דורשות Sync או Build נפרדים.
7. אמתו INIT, פעולה רגילה, שחרור או ביטול ו־STOP בהספק נמוך לפני הוספת תכונה נוספת.

אפשר גם להעתיק דוגמת FTC SDK מקורית ל־TeamCode, אך יש לפעול לפי מחזור החיים של ה־SDK ולא להניח שהיא כבר משתמשת ב־SolversLib. עץ הדוגמאות של `FtcRobotController` עצמו מוחרג מהבנייה. אין ליצור מודול Gradle חדש של TeamCode כדי להפעיל דוגמה.

## הוספת תכונה בצעדים קטנים

התחילו בגבול החומרה: מפו התקן פעם אחת, הגדירו יחידות ומגבלות וחשפו פעולות משמעותיות של תת־המערכת. הוסיפו פקודות שמצהירות על דרישות ומנקות פלט רציף בסיום או בהפרעה. לאחר מכן קשרו בקרות או הרכיבו שגרה. שמרו קואורדינטות והחלטות ניקוד ייחודיות למשחק בשגרת הקבוצה.

למנגנון איסוף התחילו משיעור מנוע מועתק ובהספקי חוג פתוח מדודים. לתופסן השתמשו בנקודות קצה מדודות של הסרוו והגדירו במפורש השהיית תנועה נדרשת. לאוטונומי הריצו תחילה מסלול קצר אחד, בדקו קצה וזווית ורק אז הוסיפו מקטע שני ותיאום מנגנונים. timeout מגביל זמן שחלף; החליטו כיצד השגרה מטפלת בכישלון לפני שפעולות ניקוד מאוחרות מניחות שהרובוט הגיע.

שנו בכל פעם משתנה פיזי או פרמטר כוונון אחד. תעדו מצב סוללה, משטח, עומס, מדידות עם סימן, יחידות ותוצאות בהערות הקבוצה; הכניסו קבועים מאושרים לקוד המקור. עריכות Panels בלבד אינן משמרות את תצורת הקבוצה.

לכיול Pedro 3 פעלו לפי [AutoTune](08-panels-tuning.md#pedro-3-autotune): שמרו פלט Mecanum בתור `drivetrainConfig`, פלט Pinpoint בתור `localizerConfig`, ולאחר מכן פלט Foresight בתור `foresightConfig` ב־Constants. החליפו כל הצהרה במקום להוסיף שדות כפולים. התקינו והפעילו מחדש אחרי שמירת כל דרישה מוקדמת. היסטי Pinpoint משתמשים כעת באינצ׳ים, ולכן יש לחלק מדידות ישנות בסנטימטרים ב־2.54. תעדו יחד תוצאות הליך וגרסת תצורה; אל תשחזרו מספרי כוונון מעונה ישנה.

## סקירה ושיתוף שינויים

לפני עריכה בדקו את **Commit / Local Changes** כדי לדעת איזו עבודה כבר קיימת. צרו ענף תכונה בבורר הענפים והשתמשו ב־**Show Diff** לפני בחירת קבצים ל־commit. הפרידו שינויים לא קשורים ואל תמחקו עבודת מתכנת אחר. הודעות commit ובקשות משיכה צריכות להסביר את ההתנהגות שהתקבלה, את הבדיקות הרלוונטיות ואת אימות החומרה שנותר.

לפני שיתוף שינוי:

- בחרו את הבקר ותצורת יישום Android והשתמשו ב־**Run ▶** לבנייה ולהתקנה. במקרה כישלון עיינו ב[פרק 09](09-troubleshooting.md).
- בדקו התקנים נדרשים, שמות OpMode מוצגים, בקרות וקישורי תיעוד.
- סקרו דרישות תתי־מערכות, פלט באתחול והתנהגות ביטול ו־STOP.
- תעדו בדיקות רובוט ומדידות ממתינות.
- החריגו נתיבי SDK מקומיים, הגדרות IDE, פלט שנוצר ופרטי גישה; שמרו את רישיון המאגר והודעות צד שלישי הרלוונטיות.

מאגר המפתחות לפיתוח FTC המסופק ב־`libs` שייך לסביבת הפיתוח; שמרו אותו כמתועד. אל תחליפו אותו בחומר חתימה אישי לייצור. בצעו שינויי תלויות ובנייה במכוון ותעדו בדיקות תאימות.

כשתשנו בהמשך את ברירות המחדל של התבנית, עדכנו יחד את המדריך, הדוגמאות ו־README. הוסיפו רשומת יומן שינויים מתוארכת המבחינה בין התנהגות שמומשה לביצועים שנמדדו ברובוט. כך המתכנת הבא יוכל לשחזר את ההגדרה העובדת בלי להסתמך על שיחה קודמת.

תרגיל: צרו עותק של שיעור המנוע בשם חדש למנגנון קבוצתי, כתבו רשימת בדיקת חומרה ובקרות ובקשו מחבר קבוצה לעקוב אחר האתחול, דרישות הפקודות ומסלול העצירה לפני ההרצה.
