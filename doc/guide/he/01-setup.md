# 01 - התקנה והרצה ראשונה

[English](../01-setup.md) | [תוכן המדריך](../../../README.he.md#learning-path) | הבא: [מבנה הפרויקט](02-structure.md)

## יצירת עותק לקבוצה

השתמשו במאגר הקבוצה שנוצר מתבנית זו. במסך הפתיחה של סביבת הפיתוח בחרו **Get from VCS** או **Clone Repository**, הדביקו את כתובת מאגר הקבוצה ופתחו את הפרויקט ששוכפל. לעותק קיים בחרו **File > Open** ובחרו בתיקיית השורש המכילה את `settings.gradle.kts`. אין לשלוח שינויים ייחודיים לרובוט למאגר המקורי של FTC SDK.

התקינו סביבת פיתוח התומכת ב־Android, כגון Android Studio Narwhal 3 Feature Drop או חדשה יותר, Git, Android SDK ו־JDK של Java 25. ב־IntelliJ נדרשת תמיכה בפרויקטי Android; אם אינה זמינה, השתמשו ב־Android Studio. פתחו **Settings > Build, Execution, Deployment > Build Tools > Gradle** והגדירו **Gradle JDK/JVM** ל־Java 25. לפי הצורך הוסיפו או הורידו אותו בבורר ה־JDK. הגדרת רמת השפה בעורך Java בלבד אינה בוחרת את סביבת ההרצה של Gradle. שמות התפריטים עשויים להשתנות מעט בין גרסאות; אפשר להשתמש ב־**Find Action** כדי למצוא פעולה לפי שמה.

התבנית משתמשת ב־Gradle 9.1.0, בתוסף SDK 12 של Dairy וב־Android Gradle plugin 8.13.2. קוד היישום מקומפל באמצעות שרשרת הכלים של Java 8 לשמירת תאימות ל־FTC. Foojay יכול להשלים שרשראות כלים חסרות כאשר הורדות זמינות. קוד מקור של Java 8 בעורך אינו אומר שיש להריץ את Gradle על Java 8.

## Android SDK והגדרות מקומיות

השתמשו ב־SDK Manager כדי להתקין את הפלטפורמה וכלי הבנייה הנדרשים בסנכרון Gradle. Dairy מגדיר כרגע compile SDK 30; תלויות מותקנות עשויות לדרוש הורדות נוספות. שמרו על מוסכמות FIRST/Dairy בנוגע ל־target/minimum SDK אלא אם מתבצעת בדיקת תאימות נפרדת.

בחרו ב־**SDK Manager** את מיקום Android SDK במחשב שלכם ואפשרו לסביבת הפיתוח ליצור את ההגדרות המקומיות ב־`local.properties`. אל תעתיקו נתיב מוחלט ממחשב אחר ואל תבחרו תיקיית JDK בתור Android SDK. הקובץ מוחרג מ־Git.

המתינו לסיום סנכרון Gradle הראשון. לאחר שינוי תלויות או הגדרות בנייה לחצו **Sync Now** כשהאפשרות מוצגת, או **Sync Project with Gradle Files** ב־Android Studio. ב־IntelliJ השתמשו ב־**Reload All Gradle Projects** בחלון Gradle. שינויים רגילים בקוד Java אינם דורשים בדרך כלל סנכרון נוסף.

תהליך העבודה היומיומי הוא: עריכת קוד, בחירת הבקר ולחיצה על **Run ▶**. הפעולה בונה ומתקינה את היישום אוטומטית; בדרך כלל אין צורך בפעולת Build נפרדת. Sync מייבא הגדרות בנייה ותלויות ואינו מתקין את היישום. ראו [מדריך הבנייה וההרצה של Android Studio](https://developer.android.com/build/building-studio).

אין ליצור `TeamCode/build.gradle` נוסף או להוסיף מודולים כדי לתקן מבנה זה של יישום יחיד. קראו את השגיאות בחלון Build/Sync לפני שינוי גרסאות; [פרק 09](09-troubleshooting.md) עוסק בבעיות נפוצות.

## הגדרת הרובוט

Starter TeleOp הפעיל דורש ארבעה מנועי mecanum בעלי שמות נפרדים, Pinpoint וגלגלי אודומטריה תואמים. השתמשו בשמות שב[טבלת החומרה](../../../README.he.md#required-hardware), או שנו את Constants לשמות שלכם. בחרו את התצורה המתאימה ב־Robot Controller. שמות התצורה מתייחסים להתקנים, ולא לשמות מחלקות Java.

הגדירו היסטי אודומטריה עם סימן, סוג גלגלים, כיווני מקודדים וכיווני מנועים לפני נהיגה ביחס למגרש. היסטי התבנית הם ערכי אפס זמניים. INIT מוצלח מעיד רק שאיתור ההתקנים והאתחול הצליחו; הוא אינו מאמת כיוונים או יחידות.

## התקנה והרצה

1. חברו את Robot Controller באמצעות USB או חיבור אלחוטי מורשה שכבר הוגדר. אשרו בבקר בקשות הרשאה לניפוי שגיאות USB. בחרו את הבקר בפועל בבורר ההתקנים. אם הוא חסר או לא מקוון, השתמשו בכלי פתרון בעיות החיבור ובדקו את הכבל וההרשאה.
2. כשהרובוט עצור, בחרו בסרגל הכלים את תצורת ההרצה מסוג **Android App** ולחצו **Run ▶**. שמה עשוי להיות **FTC-25262-Template** או **TeamCode**; השם לבדו אינו קובע את סוגה. ב־**Run > Edit Configurations** ודאו שהיא מכוונת ליישום Android שבשורש. המתינו לסיום הבנייה וההתקנה בבקר הנבחר. אין צורך ללחוץ Build תחילה. אם התצורה האחרונה הייתה משימת Sloth, חזרו לתצורת יישום Android.
3. התאימו את Driver Station לדור FTC SDK שבשימוש כאן, 12.0. שחזרו את החיבור ובחרו את תצורת החומרה הרצויה.
4. בחרו **Starter TeleOp**, לחצו INIT, קראו את הטלמטריה ואז לחצו START. בדקו כל כיוון בהספק נמוך כשהרובוט נתמך כראוי. STOP מסיים פקודות מתוזמנות ומאפס את פלטי ההנעה.

**Run ▶** בסביבת הפיתוח מתקין את יישום Robot Controller. פעולות **INIT** ו־**START** ב־Driver Station מאתחלות ומריצות את ה־OpMode הנבחר בבקר; אלה פעולות נפרדות. תצורת Java Application אינה מתקינה את יישום FTC.

ללמידה ללא ציוד היקפי, העתיקו את שיעור 01, שנו את שמות החבילה, הקובץ, המחלקה וה־annotation והסירו `@Disabled`. לחצו שוב **Run ▶** של יישום Android ואז בחרו את השיעור ב־Driver Station; הוא אינו יוצר PedroDrive ואינו קורא ל־hardwareMap. עדיין נדרש hub עם יישום Robot Controller להרצת OpMode.

## בדיקה לפני ההמשך

עליכם לדעת לזהות את Gradle JDK, מיקום Android SDK, הבקר הנבחר ותצורת החומרה הפעילה. הסבירו מתי נדרש Sync, כיצד Run בונה ומתקין, ומדוע עדיין דרושים INIT/START ב־Driver Station. תעדו את גרסאות הכלים בהערות הקבוצה כדי שמתכנת אחר יוכל לשחזר את ההתקנה.
