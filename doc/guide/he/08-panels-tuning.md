# 08 - Panels,‏ Sloth וכוונון

[English](../08-panels-tuning.md) | [תוכן המדריך](../../../README.he.md#learning-path) | דוגמה: [07 Panels](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/examples/Example07Panels.java) | הבא: [פתרון בעיות](09-troubleshooting.md)

## חיבור הדפדפן

Panels מציג טלמטריה וחושף שדות הניתנים להגדרה. הפרויקט כבר כולל את תלות FullPanels התואמת ל־Sloth; שמרו על גרסה זו כשמשתמשים ב־Sloth. אין להוסיף לצדה FullPanels רגיל.

1. התקינו את היישום המלא לפי [פרק 01](01-setup.md#install-and-run) והשאירו את יישום Robot Controller פועל.
2. חברו את המחשב לרשת ה־Wi-Fi של Robot Controller. פרטי ההתחברות מופיעים ב־Program and Manage.
3. פתחו `http://192.168.43.1:8001` עבור Control Hub, או `http://192.168.49.1:8001` עבור Robot Controller בטלפון. אלה הכתובות הרגילות ב[מדריך החיבור המקורי](https://ftcontrol.bylazar.com/docs/panels/overview/); השתמשו בכתובת הבקר בפועל אם הרשת שלכם שונה.
4. פתחו את רכיבי הטלמטריה והשדות הניתנים להגדרה. העתיקו והפעילו את Example07, ואז בצעו INIT ו־START דרך Driver Station. אין צורך במנוע, סרוו או Pinpoint.

אם הדף אינו נטען, בדקו חיבור Wi-Fi, כתובת בקר, יישום פועל ותלות מותקנת לפני שינוי קוד Java. גם VPN או מדיניות ניתוב עשויים למנוע גישה. חיבור ADB לבדו אינו מספק גישת דפדפן לכתובת ה־Wi-Fi של הרובוט. טלמטריית Driver Station שימושית גם באבחון בעיות דפדפן.

## שדות חיים ותמונות מצב

Example07 משתמשת ב־`JoinedTelemetry` לשליחת אותם ערכים ל־Driver Station ול־Panels. המחלקה מסומנת `@Configurable` וחושפת את השדה הציבורי והסטטי `REQUESTED`. אחרי START שנו אותו מ־0.2 ל־0.3 ברכיב ההגדרות והחילו את השינוי. הטלמטריה `Live field` משתנה משום שכל לולאה קוראת שוב את `REQUESTED`. הערך `Initialization snapshot` נשאר כפי שהועתק במהלך `initialize()`. בצעו STOP,‏ INIT ו־START מחדש כדי לצלם תמונת מצב חדשה.

אותה הבחנה חשובה גם במקומות אחרים:

| הגדרה | מתי התבנית קוראת אותה |
|---|---|
| `POWER` של מנוע Example02 | בכל מחזור ביצוע באמצעות ספק |
| מיקומי הסרוו ב־Example03 | באתחול הפקודה המיידית המקושרת |
| הגדרות העוקב והבקרים ב־Constants | ביצירת רכיבים ובקרים; יש להפעיל מחדש אחרי עריכה |

עריכת שדה אינה בונה מחדש בקר או מסלול קיימים. עצרו ואתחלו מחדש לאחר שינוי הגדרות שנשמרות כתמונת מצב. שמרו ערכים מספריים סופיים ובתוך מגבלות חומרה שנמדדו. תעדו ערכים מאושרים בקוד המקור: שינוי שדה בזמן ריצה אינו עריכת מקור שמורה, ואין להשתמש במשך הישרדותו בין טעינות כאחסון תצורה.

## התקנת קוד הקבוצה באמצעות Sloth

Sloth יכול לטעון מחדש קוד קבוצה לאחר התקנת יישום מלאה. תוסף הטעינה ורכיב זמן הריצה בפרויקט כבר מוגדרים. [הוראות Sloth המקוריות](https://github.com/Dairy-Foundation/Sloth#gradle-tasks) מתארות את משימות ההתקנה והסרת הקוד המרוחק; במאגר זה מריצים אותן בפרויקט השורש.

תהליך **Run ▶** הרגיל של יישום Android מפרק 01 הוא נקודת ההתחלה הפשוטה ביותר. Sloth הוא אפשרות נוספת. ליצירת כפתור פעם אחת בסביבת הפיתוח:

1. פתחו **Run > Edit Configurations**, לחצו **+** ובחרו **Gradle**.
2. קראו לתצורה **Deploy Sloth**, בחרו את פרויקט Gradle בשורש המאגר והזינו `deploySloth` בשדה **Tasks/Run**. זהו שם משימה בתצורת IDE, ולא פקודת מסוף. שמרו באמצעות **Apply/OK**.
3. כשהרובוט עצור והבקר הרצוי מחובר ומורשה, בחרו **Deploy Sloth** בסרגל הכלים ולחצו **Run ▶**.

השתמשו בכך לשינויים נתמכים בתוך `org.firstinspires.ftc.teamcode` ותתי־החבילות שלה. לאחר הטעינה בחרו ואתחלו מחדש את ה־OpMode ובדקו שינוי טלמטריה שניתן לזהות. לשינוי תלויות, משאבים, מניפסטים או רכיבים אחרים מחוץ לקוד הקבוצה הניתן לטעינה מחדש, השתמשו ב־**Run ▶** של יישום Android להתקנה מלאה.

לפני חזרה להתקנה מלאה אחרי העלאות Sloth, צרו תצורת Gradle נוספת בשם **Remove Sloth Remote**, המכוונת לפרויקט השורש עם `removeSlothRemote` בשדה **Tasks/Run**. הריצו והמתינו להצלחה, ואז בחרו בתצורת **Android App** ולחצו **Run ▶**. כך מוסר קוד שנטען מרחוק, כדי שהעלאה ישנה לא תחליף את המחלקות המותקנות.

פעולות התקנה אלה משנות את הבקר המחובר. צילומי מסך מהמקור המציגים מודול Gradle נפרד של TeamCode אינם תואמים ליישום השורש הזה. כשמחוברים מספר התקנים, ודאו שמשימת ההתקנה מכוונת לבקר הרצוי; במקרה של ספק השאירו רק אותו מחובר. בדקו משימות בחלון **Gradle**, וראו [מדריך JetBrains לתצורות הרצת Gradle](https://www.jetbrains.com/help/idea/run-debug-gradle.html) לפקדי התצורה. אין צורך ב־Build נפרד לפני ההתקנה.

## AutoTune של Pedro 3

[Tuning.java](../../../TeamCode/src/main/java/org/firstinspires/ftc/teamcode/pedroPathing/Tuning.java) רושם ארבעה הליכי כוונון; הוא **אינו TeleOp** ואין בו `@Disabled` להסרה. המימושים מותאמים מה־[Quickstart הרשמי](https://github.com/Pedro-Pathing/Quickstart/tree/9dc89787898fab6b5cd9095df38489a14bf51a95/TeamCode/src/main/java/org/firstinspires/ftc/teamcode/pedro/procedures). ראו [מקור הקוד והרישיון](../../PEDRO_QUICKSTART_SOURCE.md).

1. התקינו את היישום המלא, השאירו את Robot Controller פועל והתחברו לרשת ה־Wi-Fi שלו.
2. פתחו `http://192.168.43.1:10158` עבור Control Hub, או `http://192.168.49.1:10158` עבור בקר טלפון. החליפו בכתובת הבקר בפועל אם היא שונה. **פורט 10158 מיועד ל־AutoTune; פורט 8001 מיועד ל־Panels.**
3. בחרו הליך בדפדפן ופעלו לפי בקשות הקלט והאישור. כשההליך מבקש OpMode של כוונון, בחרו את השלב שלו ב־Driver Station והשתמשו ב־INIT/START/STOP לפי ההנחיות. אין לבחור ב־TeleOp הידני הישן בשם "Tuning". חלק משלבי המדידה מסתיימים בעצמם; אחרים מבקשים במפורש לעצור לאחר דחיפה או סיבוב ידניים.
4. פעלו בסדר הבא, ושמרו והתקינו כל תצורה שנוצרה לפני הליכים שתלויים בה.

| הליך | דרישות ותוצאה |
|---|---|
| Mecanum Tuner | הזינו ארבעה שמות חומרה. המנועים מסתובבים בנפרד; אשרו את הגלגל הנכון ואת כיוונו. החליפו את `Constants.drivetrainConfig` בבלוק שנוצר. |
| Pinpoint Tuner | הזינו `odo` (ההליך מציע בתחילה `pinpoint`), בחרו את סוג הגלגלים ובצעו דחיפות וסיבוב לפי הבקשה. החליפו את `Constants.localizerConfig` בבלוק שנוצר. |
| Tests: Pose / Localization / Driving / Odometry | אמתו כיוונים פיזיים, מרחקים מדודים וזווית לפני כוונון האלגוריתם. Pose הוא בדיקת מיקום פסיבית; בדיקות אחרות עשויות להניע את הרובוט. |
| Foresight Tuner | דורש הגדרות הנעה שמורות ומעריך מיקום שנבדק. בצעו שלבי זיהוי מהירות, תאוטה טבעית, זווית, בלימה ותנועה קווית. החליפו את כל בלוק `Constants.foresightConfig` בפלט שנוצר. |
| Tests: Hold / Line / Curve / Interpolation | דורש את שלוש התצורות השמורות. בדקו קצה, זווית, חזרתיות ו־STOP לפני שימוש בשגרות ניקוד אוטונומיות. |

### שמירת תוצאות ואימות

החליפו את ההצהרה הקיימת, ולא רק ערכי אתחול, ואל תוסיפו שדה שני באותו שם. הבלוקים משתמשים ב־`MecanumConfig`,‏ `PinpointConfig`,‏ `ForesightConfig`,‏ `DcMotorSimple`,‏ `GoBildaPinpointDriver`,‏ `DistanceUnit`,‏ `Controller`,‏ `Matrix` ו־`Vector2D`; שמרו את הייבואים הדרושים. פלט Pinpoint עבור גלגלים מותאמים דורש גם `java.util.OptionalDouble`.

המפעלים המשותפים `createDrivetrain`,‏ `createLocalizer` ו־`createAlgorithm` משמשים גם את AutoTune וגם את `createFollower`; אין תצורת רובוט נפרדת לכוונון. הליכי הגדרת מנועים ו־Pinpoint אוספים קלט חומרה משלהם, ולכן ניתן להריצם לפני כיול האלגוריתם. שמרו תוצאות, התקינו והתחילו הליך תלוי חדש.

גם יחידות ההיסטים של Pinpoint וגם יחידות המרחק הגלובלי הן **אינצ׳ים**. בהעברת היסטים ישנים בסנטימטרים חלקו ב־2.54:‏ `POD_Y_DIST` הישן ממופה ל־`xPodOffset`, ו־`POD_X_DIST` ל־`yPodOffset`. מהירויות באינצ׳ים לשנייה, תאוטות באינצ׳ים לשנייה בריבוע וזוויות בזמן ריצה ברדיאנים. שמרו את הצהרות היחידות בבלוק שנוצר.

תצורת Foresight ההתחלתית משתמשת ב־**ברירות מחדל של ספריית Pedro 3 שלא נמדדו**. מספרי המהירות והתאוטה ואומדני הבלימה הישנים מ־Pedro 2 הוסרו; הם אינם תחליף למדידה. פלט Foresight כולל בקרים מקטעיים נפרדים קדימה והצדה והתאמות עצמאיות לבקרה מקדימה בגלישה ובבלימה. העתיקו את הבלוק כולו ואתחלו מחדש; תוצאות בדפדפן ועריכות Panels אינן שומרות קוד Java אוטומטית.

קראו את תיאור התנועה של כל שלב ופנו את כל שטח התנועה לפני START. ההליכים המקוריים עשויים להשתמש בהספק משמעותי, תנועות חוזרות ומרחקים גדולים מהדוגמאות הקטנות. קלט הדפדפן אינו מגבלת הספק כללית. השאירו את STOP ב־Driver Station זמין. תעדו סוללה, משטח, עומס ותוצאות בפועל; מדידות הרובוט והתנהגות STOP עדיין מחייבות בדיקה בחומרה.

אם לא מופיעים הליכים, בדקו את היישום המותקן, הכתובת, הפורט והרשת, ושמפעלי `@Tuner` נשארו מתודות ציבוריות וסטטיות ללא ארגומנטים המחזירות בדיוק `Procedure`. הסירו קוד Sloth מרוחק ישן לפני התקנה מלאה כמתואר לעיל.

תרגיל: הדגימו את ההבדל בין ערך חי לתמונת מצב ב־Example07, והסבירו מדוע יש לשמור תוצאות Mecanum ו־Pinpoint לפני כוונון Foresight. לאחר הכוונון תעדו שלוש תוצאות של מסלול קצר הניתנות לשחזור וציינו את התצורה ששימשה להן.
